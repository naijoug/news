# HTTP 缓存策略

## 概述

本项目采用标准的 HTTP 缓存机制，实现了多层缓存优化：

1. **服务器端缓存**：减少数据库查询
2. **HTTP 缓存验证**：使用 ETag 实现高效的缓存验证
3. **客户端缓存**：浏览器自动缓存，减少网络请求

## 工作原理

### 首次请求流程

```
客户端 → 服务器 → 数据库
       ← 200 OK + ETag + Cache-Control + 数据
```

1. 客户端发起请求
2. 服务器查询数据库
3. 服务器生成 ETag（数据的 MD5 哈希）
4. 服务器缓存数据和 ETag
5. 返回 200 状态码 + 完整数据 + 缓存头

### 后续请求流程（缓存命中）

```
客户端 → 服务器（带 If-None-Match: ETag）
       ← 304 Not Modified（无数据体）
客户端使用本地缓存的数据
```

1. 客户端发起请求，带上 `If-None-Match` 头（包含之前的 ETag）
2. 服务器从缓存中获取数据和 ETag
3. 比较 ETag，如果匹配返回 304
4. 客户端使用本地缓存的数据

### 缓存失效流程

```
客户端 → 服务器（带 If-None-Match: 旧ETag）
       ← 200 OK + 新ETag + 新数据
```

1. 服务器缓存过期（5分钟后）
2. 服务器重新查询数据库
3. 生成新的 ETag
4. 返回 200 + 新数据

## 缓存配置

### 服务器端缓存

- **TTL**: 5 分钟
- **存储**: 内存（Map）
- **清理**: 每分钟自动清理过期条目

### 客户端缓存

- **Cache-Control**: `public, max-age=60`
- **含义**: 
  - `public`: 可以被任何缓存（浏览器、CDN）缓存
  - `max-age=60`: 60 秒内直接使用缓存，不发请求

### ETag

- **生成方式**: MD5 哈希（数据的 JSON 字符串）
- **格式**: `"<32位十六进制字符串>"`
- **用途**: 缓存验证，判断数据是否变化

## 优势

### 1. 性能优化

- **减少数据库查询**: 服务器端缓存 5 分钟
- **减少网络传输**: 304 响应不传输数据体
- **减少网络请求**: 客户端缓存 60 秒

### 2. 带宽节省

- 304 响应只有几十字节（vs 完整数据可能几百 KB）
- 对于移动端用户特别有价值

### 3. 标准化

- 使用标准 HTTP 缓存机制
- 浏览器、CDN、代理服务器都能理解
- 无需自定义缓存逻辑

## 缓存时间选择

| 资源类型 | 服务器缓存 | 客户端缓存 | 理由 |
|---------|-----------|-----------|------|
| 新闻列表 | 5 分钟 | 60 秒 | 新闻更新频率适中 |
| 平台列表 | 5 分钟 | 60 秒 | 平台配置很少变化 |

## 缓存失效策略

### 自动失效

- 服务器缓存：5 分钟后自动过期
- 客户端缓存：60 秒后重新验证

### 手动失效

当数据更新时（如创建/更新/删除平台），服务器缓存会在下次请求时自动更新，因为：

1. POST/PUT/DELETE 请求不走缓存中间件
2. 数据变化后，下次 GET 请求会生成新的 ETag
3. 客户端的旧 ETag 不匹配，会收到新数据

## 监控和调试

### 查看缓存状态

在浏览器开发者工具的 Network 标签中：

- **200 OK**: 服务器返回新数据（首次请求或缓存过期）
- **304 Not Modified**: 使用缓存数据（ETag 匹配）
- **Size**: 
  - `from disk cache`: 浏览器直接使用缓存，未发请求
  - `304`: 发了请求但使用缓存
  - 具体大小: 下载了新数据

### 响应头示例

```http
HTTP/1.1 200 OK
ETag: "a1b2c3d4e5f6..."
Cache-Control: public, max-age=60
Content-Type: application/json
```

## 最佳实践

### ✅ 推荐

- 让 HTTP 缓存机制自动工作
- 不要在应用层重复实现缓存
- 使用标准的缓存头

### ❌ 避免

- 不要禁用所有缓存（`no-cache, no-store`）
- 不要忽略 304 响应
- 不要在前端手动管理 ETag

## 扩展性

### 未来可以考虑

1. **Redis 缓存**: 替代内存缓存，支持分布式部署
2. **CDN**: 在边缘节点缓存静态内容
3. **Vary 头**: 根据不同条件返回不同缓存
4. **Stale-While-Revalidate**: 返回过期缓存的同时后台更新
